# Zulia 5.3.5

## Bug Fixes


- **Lists of dates written by the Excel and delimited targets can be read back.**
- **Typed Excel dates round trip unchanged on machines outside UTC.** 
- **Blank and whitespace only numeric cells read as null.** `SpreadsheetRecord` and the Excel numeric readers trim the text and return null when nothing is left, instead of handing whitespace to the number parser.


## Improvements

- **Date and Boolean list elements are supported.** `getList(index, Date.class)` and `getList(index, Boolean.class)` previously threw `IllegalArgumentException`. Elements now go through the same date and boolean parsers as single cells, so `yes`, `1`, and ISO date strings in a list read exactly as they do in a plain cell.
- **Blank list elements hold their position.** For every element class but String, a blank element reads as a null placeholder rather than failing the parse, so `1;;3` as a Long list reads `[1, null, 3]` and positions line up with sibling list columns. A blank whole cell reads as an empty list. String lists keep blank elements as text. Null elements are written back as blanks, so the round trip is stable.
- **One place to configure parsers for delimited and Excel sources.** The new `CellParsers` record holds the boolean parser, date parser, and date formatter, with `CellParsers.defaults()` and `with` methods for each. The new `DelimitedListSettings` owns the list delimiter, the parsers, and the list handler for both source configs. `DefaultDelimitedListHandler` and `DefaultExcelCellHandler` accept a `CellParsers`. Existing constructors and `DelimitedSourceConfig` setters are unchanged.
- **`ExcelSourceConfig` gains `withDateParser` and `withBooleanParser`,** matching `DelimitedSourceConfig`. Text cells read with `getBoolean` and `getDate` use them. Typed cells are still read from the cell type.
- ** The client `Fetch` command gains `setPrimaryReplicaSettings`,** matching what `Search` already exposes, so callers can direct a fetch by id to replica shards.
