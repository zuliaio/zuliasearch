# Zulia 5.4.0

## New Features

- **`zulia-signals` (beta): usage signals and search analytics.** Applications record what their users do (searches, clicks, views, exports, edits) as signals stored in a Zulia index, and answer usage questions with facet based reports. A `Signal` carries an actor (user, anonymous, agent acting for a user, service, or system), an action and a target from open vocabularies, optional search details, a duration, and typed tags. `SignalsClient` creates the index on first use, records synchronously under the default policy, or hands signals to a bounded background writer under `LOG_AND_DROP` so an outage never breaks the request being measured. Storage is one index by default or monthly partitions behind an alias, with retention that pages deletes or drops whole months. `ZuliaSearchSignals` turns a Zulia `Search` and its `SearchResult` into a search signal with query text, indexes, result count, latency, and impressions, and derives linked click signals. `UsageReports` answers active users, counts by any declared dimension, top and zero result queries, distinct targets, and daily, weekly, or monthly series. An `ActorIdMapper` with HMAC-SHA256 pseudonymizes actor ids per app. Documentation is on the [Signals Library](https://github.com/zuliaio/zuliasearch/wiki/Signals-Library) wiki page.

  The module is beta. Its API and stored schema may change in a later 5.x release based on feedback from the first deployments, and changes will be called out in the release notes.

- **SPECTER and SPECTER2 embedding models.** `KnownEmbeddingModel` in `zulia-ai` gains `SPECTER` (`sentence-transformers/allenai-specter`) and `SPECTER2` with the proximity adapter, both 768 dimensional, symmetric, CLS pooled, with a 512 token context, trained for scientific document similarity from citation links. Both expect the title and abstract joined by the tokenizer separator, `title[SEP]abstract`. SPECTER2 loads from `zuliaio/specter2-proximity-onnx`, a single graph ONNX export with the adapter traced in, since the adapter cannot be merged into the base weights and no upstream ONNX export exists. The export script, model card, and license are published alongside the model.

## Bug Fixes

- **Alias creation failed on single node deployments.** `FSIndexService.getIndexAlias` threw for an alias that did not exist yet where the MongoDB backed service returns null, and the index manager reads the existing alias before storing a new one, so every `createIndexAlias` on a filesystem backed node failed. It now returns null for a missing alias. Aliases in single node mode are covered by a new test for create, multi index update with a write index, delete and recreate, and survival across a node restart.
