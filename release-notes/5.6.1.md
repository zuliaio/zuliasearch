# Zulia 5.6.1

## New Features

- **Faster optimize on large indexes.** You can now stop an optimize at a number of segments instead of always merging each shard down to one. On a large index that is a smaller merge, so it can finish sooner and does less disk work. It also leaves several segments per shard, which search concurrency can split across. In Java use `new OptimizeIndex("myIndex").setMaxNumberOfSegments(8)`, and on the command line use `zuliaadmin optimizeIndex --index myIndex --maxSegments 8`. Without a target, optimize still merges each shard to one segment as before.

## Improvements

- **Paged searches that return full documents do less work.** Each shard used to load, highlight and analyze one extra document past the end of the page, only to work out where the next page starts. That document was never returned. Shards now skip it, so each page costs less, especially on indexes with large documents. Those pages are also smaller, so more of them fit in the query cache.
- **More query cache hits when facets are requested in a different order.** Two searches that ask for the same facets in a different order now share one cache entry, so the second one is answered from cache.
- **See when responses are too large to cache.** A search response over `shardQueryCacheMaxResponseMB` is skipped by the cache. Until now that left no trace, so it looked like the cache was not working at all. The general cache stats from `getIndexStats` now include `oversizedResponseCount`, and debug logging names the search, shard and size of each skipped response. Use it to decide whether to raise the limit.
- **Faster percentile stats.** Stats with percentiles do less work for each value they read, mostly because the percentile sketch no longer keeps a running sum, min and max that the server already tracks elsewhere. Results are unchanged.

## Bug Fixes

- **Score functions now work with negative float and double values.** A score function that used a float or double field read the wrong value for every negative number, so documents with negative values were scored incorrectly. Int, long and date fields were not affected.
- **Facet and stat groups come back in the order you requested them.** The order used to change on every server restart and could differ between nodes, so code that read groups by position could get the wrong one. A facet requested twice keeps the position of its first request.
- **Fields keep their analyzer after index settings change.** After an index settings update, a search or indexing thread could analyze a field with the default keyword analyzer instead of its configured one, which could give wrong matches or wrongly indexed text.
- **More reliable shutdown and shard close.** A node could skip its shutdown steps, and a closed shard could keep being warmed in the background. Both came from values that one thread changed and another thread did not see.
- **Interrupted threads stop promptly.** Closing several client connections after an interrupt waited 15 seconds on each one. Two internal queues also hid interrupts from callers, so code that tried to stop kept waiting on the next task.
- **Recording a signal no longer breaks the request it measures (`zulia-signals`).** A bad value such as a null target id or a negative duration threw an exception right where it was set, inside your request code, even when the client was set to `LOG_AND_DROP`. Problems are now collected and reported when the signal is built, so under `LOG_AND_DROP` a bad signal is just a counted drop and the request carries on. A signal whose search details failed is no longer recorded with the query, result count and latency missing.

## Breaking Changes

- **`QuantileSketch` no longer reports sum, average, min or max (`zulia-util`).** If you use `QuantileSketch` directly and need those values, switch to the new `SummarizedQuantileSketch` in `io.zulia.util.sketch`, which has the same methods and behaves the same as 5.6.0. Saved sketches and the format nodes exchange are unchanged, so a rolling upgrade from 5.6.0 is safe.
- **Signal builder errors arrive at `build()` instead of at the setter (`zulia-signals`).** With the default `PROPAGATE` policy, code that caught `IllegalArgumentException` around a builder setter now gets it from `build()` or `record`.

## Dependencies

The server and UI REST distributions are smaller. The OpenAPI generator now runs only at build time, so it and 42 jars it pulled in are no longer shipped. The REST API spec and Swagger UI are unchanged.
- micronaut-openapi 7.3.0 removed (micronaut-openapi-annotations 7.3.0 stays)
- micronaut-openapi-common 7.3.0 removed
- flexmark 0.64.8 removed (34 jars)
- jsoup 1.23.2 removed
- swagger-models 2.2.55 removed
- jackson-databind 3.2.4 removed from the server and UI REST runtime
- jackson-dataformat-yaml 3.2.4 removed from the server and UI REST runtime
- snakeyaml-engine 3.2 removed (SnakeYAML stays for the server config)
- jackson-core pinned to 3.2.4 to match jackson-databind
