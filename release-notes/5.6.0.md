# Zulia 5.6.0

## New Features

- **Distinct value counts.** A search can ask for the number of unique values of a sortable field across every matching document, without changing the hit list, so a result page can show the hit count beside the number of unique values of a key field, for example articles next to the journals they appeared in. In Java, `Search.addDistinctCount("journal")` adds the request and `SearchResult.getDistinctCount("journal")` reads it. `addDistinctCount(new CountDistinct("journal").setMaxGroupsPerShard(5_000_000))` raises the per shard cap. REST takes the repeatable `distinctCount=field` or `distinctCount=field:maxGroupsPerShard` parameter and returns a `distinctCounts` list. Each result carries the count and an `exact` flag. Below the per shard cap (default 1,000,000 distinct values) the count is exact. A shard past the cap reports a floor and the result is marked not exact. The field must be sortable. A string field counts its sort value, so a `sortAs` that lowercases or folds counts the folded form. Numeric, date and boolean fields compare exactly. Several fields can be counted in one search as long as their caps total no more than 16,000,000 per shard. A node whose collected keys would not fit in one internal message fails the search with the fields, the node, its shard count and the byte total in the error.
- **Shard query cache bounded by size.** Two new index settings bound the shard query cache by the bytes it holds instead of only by the number of queries. `shardQueryCacheMB` makes the cache hold that many MB of serialized responses. `shardQueryCacheMaxResponseMB` (default 8) returns a larger response without caching it, so one search with a large distinct count or an unlimited facet cannot fill the cache. Both are on `ClientIndexConfig`, `UpdateIndex`, the `@Settings` annotation and `zuliaadmin updateIndex --shardQueryCacheMB` and `--shardQueryCacheMaxResponseMB`. The pinned cache for warming searches is unbounded, so a warming search should not request a distinct count or an unlimited facet on a field with many values.
- **`CODE_RANK_EMBED` embedding model.** `KnownEmbeddingModel` in `zulia-ai` gains CodeRankEmbed (`nomic-ai/CodeRankEmbed`, MIT), a 137M parameter NomicBERT encoder fine tuned for natural language to code retrieval. It is asymmetric with 768 dimensions and an 8192 token context. Queries take the instruction prefix `Represent this query for searching relevant code: ` and code passages take none. The ONNX export loads from `zuliaio/coderankembed-onnx`.
- **`java.time` values, arrays and maps in spreadsheet targets and sources (`zulia-data`).** A `LocalDate` or `LocalDateTime` is written as a date cell in Excel (`m/d/yy` and `m/d/yy h:mm`) and as ISO text in delimited output, where before it fell through to `toString` and produced a text cell. An `Instant`, `ZonedDateTime` or `OffsetDateTime` is written as the `Date` of that instant. An array is written like a `Collection` instead of its identity string. A `Map`, including a BSON `Document`, is written as JSON text through a new `withMapHandler`. The date handler is now a `DateTypeHandler`, so a lambda written for `Date` keeps compiling and applies to the local types too. On the read side a record has `getLocalDate`, `getLocalDateTime` and `getInstant` in field and index forms, `getList` reads those element types, and `CellParsers` gains `withLocalDateParser` and `withLocalDateTimeParser`, defaulting to the ISO local forms. An Excel date cell reads as its calendar day with no time zone involved.
- **`routingEnabled` on zuliatest connections, off by default.** zuliatest built its client pool with node discovery and smart routing on, so a connection through a port forward or a load balancer learned the cluster's own addresses and failed with `UNAVAILABLE: io exception` after the first few requests. Set `routingEnabled: true` on a connection that can reach every node directly. Schema 1.1 declares the field.

## Improvements

- **Sorted searches that need scores run 1.15x to 1.72x faster.** The score is copied out of the sort values when the sort contains the score field, instead of rebuilding the query weight to populate scores, which repeated one term dictionary lookup per query term, per search field, per segment. The biggest gains are on narrow multi term searches across many fields. Hits and order are unchanged.
- **Numeric stats on single valued fields skip the multi value iteration.** A segment that holds at most one value per document is read through `NumericDocValues`, worth 1 to 6 percent on numeric stat and stat facet requests. Stat values are unchanged.
- **Facet group values carry no padding.** Each facet group doc value was sized from the ordinal count of all the document's facets and stored 4 zero bytes for every ordinal of a facet outside the group. The value is now sized to the facets it holds. Existing documents keep their padded values until they are reindexed or updated. Both forms read correctly, so no reindex is needed and search results do not change.
- **Percentile stats run on a vendored `QuantileSketch`.** The `sketches-java` DDSketch library is replaced by one JDK only class in `zulia-util` that keeps the DDSketch relative accuracy guarantee. The default mapping produces the same bins as the library, so every percentile is identical. Count, sum, min, max and average are tracked exactly instead of read off the bins. Bin counts are ints, so a sketch takes half the memory and grows linearly with the value range. A sketch merges straight from another sketch's bytes, and a merge with a different mapping or accuracy is rejected with a message naming both. `FeatureStatGenerator` in `zulia-ai` uses the same sketch and now reports the exact average, min and max.

## Bug Fixes

- **Escape sequences inside `zl:tq(...)` and `zl:ns(...)` are honored.** Values in a term set or numeric set query were taken verbatim from the token, so `field:zl:tq("10.1000\/jrnl.2011-0102-a")` sent the backslash to the index and returned nothing while the plain term form matched. The escaped form, the quoted form and the quoted escaped form now reach the index as the same term, `\uXXXX` is decoded, and a literal backslash is written doubled, matching the rest of the syntax. In the Java client, `QueryHelper.escapeQuotes` now escapes backslashes as well as quotes, so a value such as `share\reports\q1` handed to `Values` or `Terms` reaches the index unchanged where it was previously unescaped to `sharereportsq1`.
- **Fetching a document that does not exist.** The REST fetch endpoint returned `{}` with status 200 for a missing id. It now returns 404. In the Java client, `FetchResult.getDocument()`, `getDocumentAsJson()`, `getDocumentAsPrettyJson()` and `getDocument(mapper)` return null when there is no document, as `hasResultDocument()` already reported, instead of decoding empty bytes into an empty `Document`. A `META` only fetch of an existing document also has no document bytes and now returns null from `getDocument()`.
- **A `NaN` or infinite value no longer fails a stat request with percentiles.** The sketch rejects values it cannot index, so one such stored value failed the whole search. Percentiles now cover the finite values. Every stored value is still counted, and sum, min and max keep their plain double arithmetic, so a `NaN` still makes the sum `NaN` and an infinity still shows as the min or max. `zulia-ai` feature stats leave `NaN` and infinite feature values out the same way.
- **A failed parse no longer corrupts the next query on the same parser.** The server reuses query parsers across searches. When field expansion threw, the multi field processor was left with its skip flag cleared, so the next query on that parser skipped field expansion for every clause. Field aliases and wildcard field patterns went to Lucene as literal field names and matched nothing with no error, and a query that relied on the default search fields failed with `field name must not be null`. The flag is now reset at the start of every parse.
- **Command line values keep their quotes.** The shared command line setup turned on picocli's `trimQuotes`, which stripped the outer quotes from any value that started and ended with a double quote. A phrase such as `-q '"machine learning"'` reached the server as `machine learning` and matched either word, and `-q '"lung cancer" AND "machine learning"'` lost its first and last quote and became a different query. This affected `zulia search`, `zulia filter`, `zuliadump` and `zuliaexport`. Values now reach every command exactly as the shell delivered them.
- **The merge policy allows 15 percent deleted documents as intended.** `setDeletesPctAllowed` takes a percentage and was set to 0.15, which allowed only 0.15 percent deleted documents per segment and forced merges far more often than planned on update heavy indexes. It is now 15.0.

## Breaking Changes

- **Upgrade every node together when searches request percentiles.** Nodes exchange the percentile sketch in a new compact format, so a percentile stat that spans a 5.5.x node and a 5.6.0 node during a rolling upgrade does not work. Searches without percentiles are unaffected.
- **Set `shardQueryCacheMB` and `shardQueryCacheMaxResponseMB` only after every node runs 5.6.0.** Persisted index settings now load with unknown fields ignored, so a settings document written by a newer node opens on an older one in future upgrades, but 5.5.x nodes still use the strict parser. An index that keeps the defaults never stamps the fields and stays readable by older nodes.
- **`FetchResult` document accessors return null for a missing document or a `META` fetch** instead of an empty `Document`. Check `hasResultDocument()` before reading the document where code relied on the empty value.
- **The DDSketch proto classes are gone from `zulia-common`.** The `com.datadoghq.sketch.ddsketch.proto` classes generated from the copied `DDSketch.proto` are removed, `FacetStatsInternal.statSketch` field 8 is reserved, and `sketches-java` is no longer a dependency of `zulia-server`, `zulia-ai` or `zulia-ui-rest`.
- **`withDateTypeHandler` takes a `DateTypeHandler` (`zulia-data`).** A lambda keeps compiling. A class that implemented `SpreadsheetTypeHandler<T, Date>` for the date handler must implement `DateTypeHandler<T>` instead. The `CellParsers` record has two more components for the local date and local date time parsers. The three argument constructor remains and fills the ISO defaults.
