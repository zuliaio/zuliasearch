# Zulia 5.5.0

## New Features

- **Per-field default values.** A `FieldConfig` can carry an index-only `defaultValue`, a typed value matching the field type. When the stored path resolves to nothing for a document, the default feeds the field's index, sort and facet representations. The stored document is never modified. `Fill.WHOLE_VALUE` (the default) fills only a value missing for the whole document, and `Fill.EACH_ELEMENT` also fills each null or absent list element or list element sub-field. A document whose whole value came from the default does not match `field:*`. Vector fields take no default. A geo point field takes a latitude and longitude. `FieldConfigBuilder` gains typed `defaultValue` overloads and annotated classes gain `@DefaultValue`.
- **Lenient malformed value handling.** `FieldConfig.MalformedValueHandling` covers values that are present but cannot be parsed for the field type. `FAIL` (the default) rejects the document. `SKIP` drops the bad element and indexes the rest. `USE_DEFAULT` indexes the field default in its place. Both lenient modes apply per list element and write the stored field name into the `_zmff_` marker, so `_zmff_:field` finds the documents to repair and `_zmff_:*` finds every document with any malformed value. `FieldConfigBuilder.onMalformed` and `@OnMalformed` configure it. Vector fields support `FAIL` and `SKIP`. Geo point fields support all three.

## Improvements
- **Dotted stored field names descend through lists of lists.** A path such as `chapters.sections.heading`, where each element of one list holds its own list of documents, previously resolved to nothing, so the field indexed no values. The lookup now descends into the nested lists and flattens them, so every leaf value is indexed, faceted, sorted and exported. Existing documents pick this up on reindex. A leaf value that is itself a list is returned as before.
- **A reindex that fails on a document names the index, shard and document id** ahead of the cause.
- **A facet or sort value beyond Lucene's limit no longer has to fail the document.** A facet label is capped at 8,191 characters and a sort value at 32,766 bytes. Under the default `FAIL` such a value still rejects the document, now with a message naming the field, the length and the limit. Under `SKIP` or `USE_DEFAULT` that representation is skipped, the value is still indexed, and the document is marked in `_zmff_`. The sort limit is now measured in bytes, as Lucene measures it, so a long non-ASCII value that used to pass the check and then fail inside Lucene is caught the same way.

## Bug Fixes
- **A shard commit can no longer publish documents the committed taxonomy does not cover.** A commit runs the index prepare, the taxonomy commit and the index commit in that order so the committed taxonomy always holds every facet ordinal the committed index references. When back-to-back commits found no new documents, the final index commit ran its own prepare and could publish documents stored after the taxonomy commit. A crash at that point left an index referencing missing ordinals. The index commit now finishes only when the prepare froze a document set. This was the intermittent `TwoPhaseCommitStressTest` failure seen in the release workflow.

## Breaking Changes
- **Empty strings inside nested lists are values again, restoring the handling from before 4.9.4.** Since 4.9.4 a dotted stored field name dropped empty strings from a list held by a sub-document while a top-level list kept them, so `meta.tags: ["a", ""]` indexed one value and `tags: ["a", ""]` indexed two. Both now index both. On a dotted string field that means one more value with character length 0, a higher list length, and an empty sort value. On a dotted numeric or boolean field an empty string cannot be parsed and rejects the document under `FAIL`, exactly as a top-level list always has. Set `MalformedValueHandling.SKIP` on such a field if stored data relies on the drop. The lookup that keeps null placeholders, `DocumentHelper.getValueFromMongoDocument(document, path, true)`, carries a placeholder through every level of the path rather than one, and now also emits a placeholder for a list element that is null or a scalar where it previously skipped it, so an aligned export gets one cell per such element, and `ListElements.RETAIN_NULL` is its named form. `ListElements.RETAIN_NULL_NESTED` additionally keeps a nested list as one entry per outer element instead of flattening it, for callers that line up sibling paths. Under `FAIL` an empty string in a sub-document list on a dotted `NUMERIC`, `BOOL` or `DATE` field now rejects the document, and a reindex stops at the first such document, so set `SKIP` on those fields before reindexing an index that can hold one.
- **Malformed geo points and vectors now reject the document under `FAIL`.** A geo point that is not a document, a GeoJSON Point without numeric coordinates, a non-numeric coordinate, or one coordinate without the other previously indexed nothing for the field or failed with a raw cast error, and a vector that was not a list of numbers was skipped silently. Both now reject the document with a message naming the field and the value. A geo point document carrying neither coordinate key is still treated as absent. For a geo point configured with top-level keys, a document without coordinates no longer matches `field:*`. Set `MalformedValueHandling.SKIP` on the field to keep such documents indexable and query `_zmff_:<field>` to find them.
- **Unparseable values in facet-only numeric fields, and in boolean fields with a facet or sort but no index, now reject the document.** Values are parsed once per field, so these fields are as strict as indexed ones. Earlier releases faceted an unparseable numeric string as raw text and skipped an unparseable boolean silently. Existing indexes are unaffected until a document is stored again or the index is reindexed. To keep such documents indexable, set `MalformedValueHandling.SKIP` on the field before reindexing and query `_zmff_:<field>` for the documents to repair. A field config with no index, facet or sort is never parsed.
- **Numeric values stored as strings now facet as the parsed number.** A `NUMERIC_INT` value stored as `"007"` produced the facet label `007` and now produces `7`, whether or not the field is also indexed. Drill-down queries on the old label stop matching after a reindex. A `NUMERIC_FLOAT` or `NUMERIC_DOUBLE` value stored as `"1.50"` now facets as `1.5` for the same reason.
- **Hierarchical facets on `BOOL` fields now label `True` and `False`,** matching the flat facet. They previously used the raw stored text, so `"Y"` faceted as `Y`.
- **A facet or sort on a vector field is rejected.** A vector has no label to facet and no order to sort, so `facetAs` or `sortAs` on a `VECTOR` or `UNIT_VECTOR` field fails create and update with a message naming the field. An existing index carrying one must drop it before its next `updateIndex`.
- **Configure defaults and malformed handling only after every node runs 5.5.0.** Index settings carrying the new fields do not parse on an older release. A pre-5.5.0 node fails to start once any index carries one, and older REST clients and an older `zuliarestore` fail to read that index's settings.
