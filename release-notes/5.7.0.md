# Zulia 5.7.0

## New Features

- **`zuliatest` can compare a run against an earlier run.** A new `values` section records named results, such as a count or the top value of a facet, into a JSON run report written with `--reportOutput`. A later run loads that report with `--previousReport` and reads the values in any test as `saved.name`, for example `allPubs.count >= saved.pubsCount`. The first run uses `--recordBaseline`, which marks the tests that need a previous report as SKIPPED and writes the report the next run loads. A `saved` name that is not in the report is an error that lists the names that are, so a typo is never compared against `undefined`.
- **Date templates in `zuliatest`.** Query strings and test expressions accept placeholders that resolve to a date. There are aliases such as `${today}`, `${oneYearAgo}` and `${startOfLastYear}`, and date math such as `${now-90d}` and `${now-1y/y}`. An optional format follows a bar, as in `${today|yyyy}`. A test can now compare this year to date against the same point last year without anyone editing the config. `--asOf 2026-06-30` pins the date for a repeatable run.
- **Variables in `zuliatest`.** A `variables` section defines values once. Expressions read them by name and query strings read them as `${name}`. `--var name=value` sets or overrides one from the command line.
- **Shared JavaScript in `zuliatest`.** A `functions` section defines named helpers that every test and value can call. A `script` block runs once before the tests, for constants and anything else the tests share. A `date()` function gives that JavaScript the same date math as the templates.

## Improvements

- **Clearer `zuliatest` results.** Each test is now PASS, FAIL, ERROR or SKIPPED, in the CSV and in the run report. A test whose expression cannot be evaluated is marked ERROR with the reason, and the rest of the run continues. Before, the first bad expression stopped the run and no CSV was written.
- **`zuliatest` config schema 1.2.** The editor schema covers the new sections and is published at `https://zulia.io/schema/zulia_testing_schema-1.2.json`. Schema 1.1 stays published for older configs.
- **`ZuliaTestRunner.run()` for Java callers (`zulia-testing`).** It returns a `TestRun` with the test results, the recorded values and the run report. `runTests()` and the protected hooks work as before.

## Bug Fixes

- **A facet value could be listed twice on a shard, with its count split.** On a facet where a few values appear on most documents while new values keep arriving, a new value could be given a second ordinal in the shard's taxonomy. From then on that shard counted the value under both. The taxonomy writer cache now asks for a taxonomy reader reopen exactly when it drops a value the reader has not seen. Reopens also happen less often, about a quarter to half as many in testing. The fix does not repair a shard that already holds a duplicate. Reindex is needed to repair it. The issue is rare.

## Breaking Changes

These all apply to `zuliatest` configs and the scripts that run them. Servers, clients and indexes are not affected, so a rolling upgrade from 5.6.1 is safe.

- **Exit code 2 is new.** Exit code 1 now means every expression was evaluated and at least one test failed. A test or value that could not be evaluated gives exit code 2. A script that checks only for exit code 1 should treat any nonzero code as a failed run.
- **`${...}` in a query string or a test expression is now a placeholder.** A JavaScript template literal in a test expression has to move into a `script` block or a function `body`. An unknown name such as `${tomorrow}` in a query string stops the run before any search, with the list of aliases. In a test or value expression it is an ERROR for that test or value, and the run continues.
- **Names are checked before any search runs.** Two tests can no longer share a name. A search can no longer be named `date` or after a JavaScript built-in such as `JSON`. A search cannot be named `saved` when `--previousReport` or `--recordBaseline` is used.
